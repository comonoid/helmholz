# Гейт качества C (helmholz)

Политика — в `CLAUDE.md` (раздел «C CODE QUALITY GATE»). Здесь ПРОЦЕДУРА:
какие команды, в каком порядке, что считается гейтом, а что базой.

## Команды (канон)

| команда | что делает | цена |
|---|---|---|
| `make check-staged` | S0–S2 по изменённым/индексированным `.c/.h` | секунды |
| `make check-fast` | S0–S2 по всему живому слою | ~10 с |
| `make check` | S0–S4 по всему живому слою (главный статический гейт) | минуты |
| `make gate` | статика + `lean` + CBMC + ASan/UBSan + uninit + integer + FPE + valgrind | долго |
| `make gate-digest` | таблица ВСЕХ находок (вход для триажа) | как `check` |
| `make gate-baseline` | дописать новые находки в базу с вердиктом «НОВОЕ» | как `check` |
| `make check-fpe` | FP-ловушка (FE_INVALID\|FE_DIVBYZERO) на быстрых тестах | секунды |
| `make test-asan` / `test-uninit` / `check-int` / `valgrind` | рантайм-слой по отдельности | секунды–минуты |
| `make fuzz` | фаззинг НЕДОВЕРЕННОГО входа (OBJ и PPM) под ASan/UBSan | `FUZZ_TIME` с на цель (60) |

Фаззинг — **отчёт, не гейт**: находки однозначны (крэш/утечка), но кампания
конечна, поэтому «чисто» не доказывает ничего, а «упало» доказывает всё.
Зёрна — `tests/fuzz_seeds/` (в git) плюс реальные сцены из `assets/synth`,
если они скачаны. Крэши падают в `build/fuzz/artifacts/` и обязаны войти в
журнал находкой, а не быть перезапущенными «до зелёного».
Замер 07-10 (5 минут, ASan+UBSan+LSan, корпус 13 obj / 2 ppm): OBJ — 3.58 млн
прогонов (23.7 тыс/с, 4038 новых единиц корпуса), PPM — 2.82 млн (18.7 тыс/с);
крэшей и утечек ноль. Пик RSS 456/442 МБ. Прежний прогон (16 с) — 327 тыс.

CTU (межмодульный clang-анализ) в этом пине **не воспроизводится** (проверено
07-10): naive-режим `-analyzer-config experimental-enable-naive-ctu-analysis=true`
не импортирует тела (контрольная пара «caller/callee» ловится внутри одного TU и
НЕ ловится через CTU), а CodeChecker 6.28 отвергает `--ctu` с clang 21.1.8
(«CrossTranslation Unit options can only be enabled if clang itself supports it»).
Не тратить время повторно без смены пина.

Один файл: `scripts/cgate.sh --stage=0,1,2,3,4 ФАЙЛ`.

Ступени: **S0** clang-format (не мутирует), **S1** `gcc -O2 -c -Werror`
(+`-Wjump-misses-init`), **S2** cppcheck, **S3** clang-tidy (`-p build`),
**S4** `gcc -O0 -fanalyzer`. Ранний выход: новая находка на дешёвой ступени
останавливает дорогие. Логи — `build/cgate/logs/`, отчёт — `build/cgate/report.tsv`.

S3 гейтит **по политике**, а не по коду возврата: блокирующие классы перечислены
в `tidy_blocks` (`scripts/cgate.sh`) — `clang-analyzer-core.*`, `unix.Stream`,
`bugprone-suspicious-realloc-usage`, `bugprone-integer-division`,
`bugprone-suspicious-memory-comparison`, `bugprone-misplaced-widening-cast`, а
для `src/**` дополнительно `unix.Malloc` и
`bugprone-implicit-widening-of-multiplication-result`. Остальное (гигиена
`cert-err34-c` / `misc-include-cleaner`, «optin»-классы, widening в
`tools/`/`tests/`) идёт в `build/cgate/advisory/` и печатается сводкой:
**не блокирует ≠ не существует**. Разбор 07-10: 224 строки советов → 210 после
точечных правок; сплошной перевод индексной арифметики на 64 бита НЕ нужен
(порог переполнения `k·i` — 715 млн…2.1 млрд элементов, это 5.7…150 ГБ буфера;
продакшн-сайты починены, остальное — литералы и счётчики ≤512).

**Один прогон за раз.** Отчёт живёт в `build/cgate/`, и два одновременных прогона
затирали бы друг другу `rows/all/advisory` (07-10: параллельный прогон по двум
файлам обнулил отчёт полного и тот отчитался «46 советов» вместо 210). Теперь
`cgate.sh` берёт `flock` на `build/cgate/.lock` и второй прогон ЖДЁТ.

## База и ратчет

`scripts/cgate-baseline.txt` — разобранные находки: `файл⇥ступень⇥класс⇥текст⇥вердикт`.
Гейт валит только НОВОЕ. Вердикт обязан быть содержательным:

- `FP (механизм …)` — почему движок ошибается, с командой минимального репро;
- `ОСОЗНАННО (…§…)` — почему так и должно быть, со ссылкой на §;
- `НОВОЕ — требует вердикта` — не разобрано, гейт этим не «зеленеет».

Ключ нормирован БЕЗ номера строки (сдвиг строк не обнуляет базу) и с именами
переменных из `note:`-строк (иначе класс `jump skips variable initialization`
схлопнулся бы в одну запись на файл).

**Доказательство обязано жить в git.** Минимальные репро к записям базы лежат в
`tests/repro/` (README рядом, команда запуска внутри): `build/` чистится, и
вместе с ним исчезло бы доказательство. Если у вердикта написано «РЕПРО» —
файл из `tests/repro/` существует и воспроизводит срабатывание; если
«ПРОЧИТАНО В КОДЕ» — это заявка без инструментального доказательства (долг).

**Deadweight (`make lean`)**: осознанно неиспользуемое вычитается по
`scripts/lean-allow.txt` (публичный API архивной линии + точки входа
CBMC/libFuzzer). Гейтят `unusedFunction`/`unusedVariable`/`unreadVariable`/
`redundantAssignment`; `unusedStructMember` печатается «к сведению» и НЕ гейтит —
cppcheck разбирает заголовок в отрыве от пользователей и зовёт неиспользуемыми
все поля структур (в т.ч. `hz_objmesh::nt/v/vn`, которые читает весь проект).
Настоящий мёртвый код (ноль вызовов где угодно) — удалять: так ушли
`hz_sw_dirsum`, `pg924_hash`, `tri_trace_on`, no-op в `tools/kitfront.c`.

## Правка .c/.h — порядок

1. `clang-format -i ФАЙЛ` (S0 — иначе гейт остановится на формате).
2. `scripts/cgate.sh ФАЙЛ` → до `>>> cgate: CLEAN` (либо находка в базу с вердиктом).
3. Опасное (обход/правка деревьев, разборщики, недоверенный вход) — `make cbmc`.
4. Рантайм: `make test-asan` (и `check-fpe` для численных путей).
5. Перед коммитом: `make lean` (межфайловый мёртвый код).

## Триаж находки (контракт)

На КАЖДУЮ находку — сначала **минимальный репро**, потом решение. Правило
проекта: «похоже на известный FP-класс — собери минимальный репро, прежде чем
править настоящий код вокруг» (CLAUDE.md, п. 2).

Готовый рецепт для субагента (экономит контекст основного агента):

1. `make gate-digest` → таблица `файл⇥ступень⇥класс⇥текст`;
2. субагенту отдаётся: дайджест + список файлов; требование — на каждую находку
   вердикт `РЕАЛЬНАЯ / FP / КОСМЕТИКА` с меткой `ЗАМЕРЕНО / ПРОЧИТАНО В КОДЕ /
   РАССУЖДЕНИЕ` и минимальным репро в `build/probe_*/`;
3. реальные правки применяются в основной сессии, потом
   `make check-staged && make gate-baseline` (вердикты в базе).

## Чего гейт НЕ ловит (говорить это в докладах прямо)

- логику свипа и физику поля: статика видит память и типы, не смысл;
- ошибку, которая происходит только на пути, который ни разу не выполнился
  (прецедент 07-10: `goto done` мимо инициализаторов дал UB на пути отказа,
  ASan его не показал — слоты случайно были нулевые);
- многопоточные гонки: замеры только `OMP_NUM_THREADS=1` (А1313), побитовый
  контроль — тоже;
- GPU-ядра (`.cu/.cl`) — их не видит ни один движок гейта (см. CLAUDE.md, п. 6).
