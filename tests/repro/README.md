# tests/repro — минимальные репро к записям базы гейта

ЗАЧЕМ ЭТО В РЕПОЗИТОРИИ. Правило проекта (CLAUDE.md, п. 2): «похоже на известный
FP-класс — собери минимальный репро, прежде чем править настоящий код». Записи в
`scripts/cgate-baseline.txt` ссылаются на файлы отсюда, поэтому они обязаны жить в
git, а не в `build/` (каталог сборки чистится — доказательство исчезло бы вместе с
ним). Здесь лежит РОВНО то, на что ссылается база: уменьшенные файлы той же формы,
что и места находок.

ЭТО НЕ ТЕСТЫ И НЕ СБОРКА. Файлы намеренно урезаны (иногда с заведомо «мёртвыми»
ветками), в `make test` и в гейт не входят: `tests/*.c` гейт берёт, а вложенный
`tests/repro/*.c` — нет (glob в cgate.sh одноуровневый). Если сюда когда-нибудь
попадёт настоящий код — это ошибка.

ЗАПУСК (S3, clang-tidy; ровно эта команда даёт срабатывание):

    nix-shell shell.nix --run "OMP_NUM_THREADS=1 timeout 60 clang-tidy --quiet \
      tests/repro/ФАЙЛ.c -- -I src -I src/nstruct -std=gnu11 -fopenmp"

(`-I src/nstruct` нужен срезам `pyr.c`: он делает `#include "pyr.h"`.)

| файл | к какой записи базы | что показывает |
|---|---|---|
| `f1_sweep_gx.c` | sweep.c S3 «left operand of '*'» | срабатывание ВОСПРОИЗВОДИТСЯ |
| `f1_fixed.c` | то же | одна запись на индекс вместо пары `x[i]`/`x[n-1-i]` — срабатывания НЕТ |
| `f2_sweep_hash.c` | sweep.c S3 «right operand of '^'» | срабатывание ВОСПРОИЗВОДИТСЯ |
| `f2_fixed.c`, `f2_fixed2.c`, `f2_fixed3.c`, `f2_nosort.c`, `f2_merged.c` | то же | НИ ОДИН из вариантов не снимает: прибор теряет связь «число записей ↔ `first`» |
| `f3_grid.c` | pgather.c S3 «Assigned value is uninitialized» | срабатывание ВОСПРОИЗВОДИТСЯ |
| `f3_fixed2.c` | то же | повторная проверка `ncell <= 0` — срабатывания НЕТ |
| `f4_root2.c` | pref.c S3 «right operand of '-'» | срабатывание ВОСПРОИЗВОДИТСЯ |
| `f4_local2.c` | то же | граница снята в локальную `nt` — срабатывания НЕТ |
| `f5_pyr_cut.c` | pyr.c S3 «compound assignment uses uninitialized memory» | срез `sed -n '1,387p' src/nstruct/pyr.c`, срабатывание ВОСПРОИЗВОДИТСЯ |
| `f5_pyr_memset.c` | то же | `memset` всего региона — срабатывания НЕТ |
| `cbmc_gl.c`, `cbmc_gl_small.c` | открытый пункт: формальное доказательство F1 | CBMC 6.9.0 не сходится (таймаут) — доказательство НЕ закрыто |

ЧЕГО ЗДЕСЬ НЕТ. Старый `build/probe_triage/repro_1194_fp.c` (из первого разбора)
в текущем пине больше НЕ воспроизводится — в базе он не упоминается, ссылаться на
него нельзя. S4-близнецы (`gcc -O0 -fanalyzer`) на этих уменьшенных файлах не
воспроизводятся: записи S4 в базе помечены «ПРОЧИТАНО В КОДЕ», а не «РЕПРО».
